# Documentation

Everything except the [README](../README.md), which is the entry point and the longest single
document.

| Document                                 | What it covers                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [README](../README.md)                   | Pitch, the zero-to-working quick start, per-framework recipes, the full `TelemetryOptions` table, logging, redaction, storage, uploading, the diagnostics report, `fromEnv`, bundle size, the 20-question FAQ, and a troubleshooting table.                                                                                                                                   |
| [ARCHITECTURE.md](ARCHITECTURE.md)       | The capture pipeline and log batch as Mermaid flowcharts, sequence diagrams for one error / one log batch / offline-to-online recovery, the `uploadStatus` state diagram, the module layout, the diagnostics-export path (a gate-by-gate flowchart, a sequence diagram and its failure branches), and the load-bearing mechanisms: the `Symbol.for('logvault@1')` dual-copy guard, the serial write queue, the re-entrancy guard, the rate limiter and the identity `WeakSet`. |
| [API.md](API.md)                         | Every symbol exported from `src/index.ts`, grouped and alphabetised, with signature, parameter table, return value and example. Includes the `@codewithrajat/rm-logvault/react`, `/vue`, `/angular`, `/axios`, `/fetch`, `/react-query` and `/testing` subpaths, and a list of what is deliberately _not_ exported.                                                                         |
| [CONFIGURATION.md](CONFIGURATION.md)     | The exhaustive option reference, the precedence rule (explicit option > `fromEnv` layer > built-in default), the invalid-value rules for numbers / strings / levels, how to read the resolved config back, and five copy-pasteable presets: minimal, production, staging-with-everything, GDPR-strict and air-gapped.                                                     |
| [OPTIONS-CHEATSHEET.md](OPTIONS-CHEATSHEET.md) | The complete `TelemetryOptions` object in one block, every option with its real default inline, then an entry per option: what it means, what it does and does not do, what `true` / `false` / `0` / an invalid value resolves to, its limits, when it is read, and every callback signature. Includes the master-switch interaction map, the `DiagnosticsExportOptions` table and six copy-pasteable presets. |
| [REST-CONTRACT.md](REST-CONTRACT.md)     | The wire format: a JSON Schema (draft 2020-12) for the batch envelope, a worked `curl` request and response, the status-code table, `Retry-After` semantics, the server's obligations (durable accept before 2xx, tolerate duplicate `id`s), minimal Express and Fastify handlers, and the idempotency recommendation.                                                    |
| [SECURITY.md](SECURITY.md)               | OWASP-aligned threat model, the redaction design and its patterns, the hard limits, XSS safety of the report by construction, prototype-pollution and ReDoS safety, the endpoint allow-list, the "only egress is the configured endpoint" guarantee, supply-chain posture, the fail-closed/fail-open policy and the disclosure policy.                                    |
| [PRIVACY-GDPR.md](PRIVACY-GDPR.md)       | Lawful basis options, the data categories stored field by field, retention defaults (7 days for errors, 3 for logs) and how to change them, the `consent()` gate and exactly when it is evaluated, `clearTelemetryData()` for erasure, the subject-access path via the diagnostics export, a DPA/records-of-processing checklist, and a copy-pasteable consent banner.    |
| [BROWSER-SUPPORT.md](BROWSER-SUPPORT.md) | Which engines ship IndexedDB and why no wrapper is needed, then the limits that are browser policy rather than library behaviour: Safari's seven-day cap on script-writable storage, private windows, third-party partitioning and opaque origins, quotas and eviction, a blocked upgrade, and site data cleared mid-session — each with what `StorageFailureReason` and `StorageState` it produces, and how to verify the state on your own machine. |
| [TROUBLESHOOTING.md](TROUBLESHOOTING.md) | Twelve symptoms as `###` headings, each with symptom, cause, diagnosis and fix — storage unavailable, nothing uploading, shortcut not firing, CORS, CSP `connect-src`, records stuck in `failed`, empty report, errors missing while logs are stored, missing info-level logs, duplicate records, bundle over budget, and missing pre-init errors.                                                                                                                             |
| [DECISIONS.md](DECISIONS.md)             | An ADR-style log of the decisions that shaped the library, with context, alternatives considered and consequences for each, followed by an "assumptions made" section covering the runtime, time and ordering, delivery, the host application, and process assumptions.                                                                                                |
